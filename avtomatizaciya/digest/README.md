# Автоматизация «Дайджест новостей» · модуль 4

Утренний сбор новостей из трёх RSS в Google Таблицу и вечернее сообщение в Telegram.
Между n8n и таблицей — веб-приложение Google Apps Script. Страница проекта
(`projects/p4-daydzhest`) читает тот же адрес через `GET`.

| Файл | Что это |
|---|---|
| `Code.gs` | скрипт таблицы: `doGet` отдаёт новости, `doPost` пишет их с ключом |
| `n8n/sbor-novostey.json` | процесс «Дайджест: сбор новостей» (8:00) |
| `n8n/vecher-v-telegram.json` | процесс «Дайджест: вечером в Telegram» (19:00) |
| `../compose.yaml` | n8n с переменными `DIGEST_URL`, `DIGEST_KEY`, `TELEGRAM_*` |
| `../.env.example` | образец `.env`: ключ и адрес в Git не попадают |

## Что проверено локально

Google-аккаунта и бота в этой среде нет, поэтому проверена та часть, которая от них
не зависит (16.11.2026):

- оба JSON импортируются в n8n 2.45.4 (`import:workflow` — «Successfully imported 1 workflow»);
- процесс «Сбор новостей» целиком прошёл на настоящих лентах Хабр, 3DNews, iXBT:
  15 свежих новостей, ответ модели, проверка тегов, запись — `{"added": 15}`;
- повторный запуск дал `{"added": 0}`: скрипт не дублирует новости;
- `Code.gs` отдельно проверен с заглушками Google: неверный ключ → `{"error":"Неверный ключ"}`,
  запись → `{"added":1}`, повтор → `{"added":0}`, `doGet` вернул объект с `tags: "ИИ, наука"`;
- узел «Текст сообщения»: 15 новостей — 2491 знак; 60 новостей — 3723 знака и хвост
  «…и ещё 33 — на странице дайджеста», предел Telegram 4096 не превышен; пустая лента — `[]`;
- страница проекта опубликована на [kruStrip.github.io/digest](https://krustrip.github.io/digest/):
  пока адрес Apps Script не подставлен, она читает демонстрационный JSON в том же формате.

Осталось выполнить шаги с аккаунтом Google и ботом — они ниже.

## §1 Таблица

1. [sheets.new](https://sheets.new), название «Дайджест новостей», лист — `news`.
2. В строку 1 от A до G: `id`, `date`, `source`, `title`, `summary`, `tags`, `link`.
3. Расширения → Apps Script, проект «Дайджест», вставить `Code.gs`, сохранить.
4. Настройки проекта (шестерёнка) → Свойства скрипта → `KEY` = длинная случайная строка.
   Нажать «Сохранить свойства скрипта». Ключ записать в `../.env`.

Пометка `/** @OnlyCurrentDoc */` в первой строке обязательна: без неё Google попросит
доступ ко всем таблицам аккаунта.

## §2 Публикация веб-приложения

1. «Начать развертывание» → «Новое развертывание» → тип «Веб-приложение».
2. Запуск от имени владельца, доступ — «Все».
3. Разрешить доступ: Advanced → Go to … (unsafe) → Continue. На экране согласия должно
   быть только «View and manage spreadsheets that this application has been installed in».
4. Скопировать URL, оканчивающийся на `/exec`.

Проверка из терминала:

```bash
URL=https://script.google.com/macros/s/…/exec
curl -sL "$URL" | head -c 400; echo
curl -sL -H "Content-Type: application/json" -d '{"key":"неверный","news":[]}' "$URL"; echo
```

Пустая таблица отвечает `{"news":[]}`, неверный ключ — `{"error":"Неверный ключ"}`.
После изменения `Code.gs` нужно создать новое развертывание: правка файла не меняет
уже опубликованный адрес.

## §3 Модель

Нужна модель `qwen3.5:4b` в Ollama на компьютере (глава 4.3):

```bash
ollama pull qwen3.5:4b
ollama run qwen3.5:4b "Ответь одним словом: работает?"
```

В узле «Модель» вместе с именем модели передаётся `think: false`. Без этого флага
модель сначала пишет длинные рассуждения: одна новость обрабатывается около минуты,
а пятнадцать новостей не укладываются в таймаут. С флагом ответ приходит примерно
за 1,6 секунды. `qwen3:4b-instruct` из главы 4.3 в реестре сейчас недоступна,
поэтому взята установленная `qwen3.5:4b`.

n8n в Docker обращается к ней по `http://host.docker.internal:11434`. На Linux адрес
работает благодаря строке `extra_hosts` в `compose.yaml`.

Если Ollama поднята сервисом из этого же `compose.yaml` (порт 11435), в узле «Модель»
замените адрес на `http://ollama:11434/api/chat` и выполните:

```bash
docker compose exec ollama ollama pull qwen3.5:4b
```

## §4 n8n

1. Заполнить `../.env` (не коммитится):

```
DIGEST_URL=https://script.google.com/macros/s/…/exec
DIGEST_KEY=ваш ключ
TELEGRAM_TOKEN=токен бота
TELEGRAM_CHAT_ID=номер чата
```

2. Перезапустить n8n, чтобы он увидел переменные:

```bash
cd avtomatizaciya
docker compose up -d
```

3. Импорт процессов: n8n → меню → Import from File → `n8n/sbor-novostey.json`,
   затем `n8n/vecher-v-telegram.json`.

4. Открыть «Дайджест: сбор новостей», нажать Execute. Ожидаемый итог: ленты → свежие
   новости → «Модель» → «Проверка ответа» → «Запись в таблицу» с ответом `{"added": N}`.
5. Открыть таблицу: строки с пересказом и тегами на месте.
6. Нажать Publish. Процесс будет запускаться ежедневно в 8:00 по Москве.
7. «Дайджест: вечером в Telegram» → Execute, проверить сообщение в Telegram → Publish (19:00).

Теги в схеме ответа описаны массивом строк без `enum`: со списком допустимых значений
Ollama 0.40.12 не отвечает. Лишние теги отбрасывает узел «Проверка ответа».

## §5 Страница дайджеста

В `projects/p4-daydzhest/.env` и в переменной репозитория `VITE_DIGEST_URL` указать
тот же адрес `/exec`. Страница только читает: ключ ей не нужен и в код не попадает.

Проверка данных до подключения страницы:

```bash
curl -sL "$DIGEST_URL" | head -c 300; echo
```

Ответ должен содержать `{"news":[{"id":…,"tags":"ИИ, наука",…}]}`.

## §6 Частые ошибки

| Что видно | Причина | Что сделать |
|---|---|---|
| Просят доступ ко всем таблицам | нет `@OnlyCurrentDoc` | отменить, добавить пометку, развернуть заново |
| Ответ — HTML вместо JSON | повторный `POST` после 302 (`curl -X POST -L`) | убрать `-X POST`, оставить `-d` |
| `{"error":"Неверный ключ"}` | ключ в `.env` не совпал или n8n не перезапущен | сверить ключ, `docker compose up -d` |
| `URL is not defined` в «Свежие новости» | в Code-узле n8n нет `URL` браузера | разбирать строкой: `link.split('/')[2]` |
| Узел «Модель» висит минутами | в схеме массива указан `enum` | оставить массив строк, лишнее отсекать кодом |
| `connect ETIMEDOUT …:11434` | n8n не видит Ollama | проверить `extra_hosts` и что Ollama слушает 11434 |
| Соединение с Google оборвалось | сеть | у «Запись в таблицу» включён Retry On Fail, 3 попытки |

## Что осталось сделать вручную

- Создать таблицу и развернуть `Code.gs` (нужен аккаунт Google).
- Вписать ключ и адрес в `avtomatizaciya/.env`, перезапустить n8n.
- Запустить оба процесса, проверить строки в таблице и сообщение в Telegram.
- Подставить `/exec` в переменную репозитория `VITE_DIGEST_URL` и пересобрать сайт.
