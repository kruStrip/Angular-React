# Задание 4. Доступность и публикация

## Что сделать

- Проверить страницу Lighthouse в категории Accessibility (Chrome, режим
  «Снимок настольного компьютера»).
- Пройти страницу клавишей Tab: поиск → тег → флажок → ссылки заголовков → кнопки
  «прочитано». Фокус всегда виден, порядок совпадает с порядком на экране.
- Исправить всё, что нашлось: подписи полей, контраст, порядок заголовков.
- Добавить `.github/workflows/deploy.yml`: перед сборкой — `npm run lint -- --deny-warnings`
  и `CI=true npm test`, затем публикация `dist` на GitHub Pages.
- Адрес данных для сборки брать из переменной репозитория `VITE_DIGEST_URL`; если она
  не задана — использовать демонстрационный `data/news.json`.

## Правила проекта

- Не отключать проверки и не добавлять `aria-*` «на всякий случай».
- Механизмы доступности — нативные: `label`, `button`, `select`, `time`, видимый фокус.
- Секретов в конвейере нет: адрес веб-приложения открытый.

## Готово, когда

- Lighthouse Accessibility — 100;
- Tab проходит все элементы, Enter и Space нажимают кнопки, флажок переключается
  с клавиатуры;
- `deploy.yml` запускается на push в `main`, линтер и тесты идут до `npm run build`;
- сайт открывается по адресу GitHub Pages, новости загружаются, отметка «прочитано»
  переживает F5;
- в README проекта — ссылки на репозиторий и сайт.
